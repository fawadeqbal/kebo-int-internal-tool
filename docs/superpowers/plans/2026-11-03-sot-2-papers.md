# Single source of truth · PR 2 of 5: papers that never move

From the audit (docs/superpowers/specs/2026-11-03-single-source-of-truth-audit.md §1 #4 #7, §3.5, §3.6,
§3.8, §3.9, §5, §7, §8 "PR 2") and the owner decisions in §10. Builds on PR 1 (one money truth, merged).

1. Stored numbers for live papers: `Payment.receiptNo` and `PaymentPlanItem.requestNo` (or an OrderPaper row
   created on first print — pick the simpler one that keeps numbers forever). Assigned once, never reused,
   never renumbered when a payment is voided, back-dated or the plan is rebuilt (a rebuilt plan keeps the
   request numbers of rows it keeps; new rows get the next number). Migration backfills existing numbers
   in today's order (paidOn, createdAt; voided payments keep theirs if they had been printed — else skip).
2. Proforma (and packing list once shipped) become frozen papers like the others: issuing the proforma
   makes it final with a snapshot of exactly what it printed (lines, totals, terms sentence, buyer, our
   bank details, company). Re-printing the same number shows the snapshot. "Make again" makes v2 with the
   same number (as other papers). Migration: snapshot every issued PI now, marked "rebuilt from the data
   on <date>". Order.proformaNo/IssuedOn become an index (kept in step only by the issue action).
3. Buyer frozen AT THE ORDER (owner decision): `Order.buyerSnapshot` (name, address, country, tax/reg no.,
   contact) taken when the order is made (from the accepted revision's customerSnapshot merged with the
   customer as it is then). Every order paper reads it (remove the field-by-field merge in
   papers.service/documents.service; align the web print helper `customerOr`). The papers' Make page shows
   "Buyer as on the order · Refresh from customer" — refresh asks a reason, records it in history, and
   only affects papers made afterwards (final papers keep their snapshot). Backfill from the revision's
   snapshot merged as today (so nothing printed today changes).
4. Terms follow the route: stop `setRoute` writing `Order.balanceTerms` (keep it frozen = as accepted).
   Payment sentences on proforma / sales contract / payment request are built from the route (paymentRoute
   + balanceWhen/lcTerms/lcDays + plan). The quotation's free-text paymentTerms is printed only while the
   route is still the accepted one; when they differ the Make page shows a check "The quotation said
   '<text>'; the route is now <route>" with a choice to print it or not (default: not).
5. OrderDocument refuses rows of kinds the app makes (proforma, packing list, sales contract, commercial
   invoice…) — API 400 with a clear message; the document form hides those kinds. Migration: hand-made
   rows of those kinds: keep their files as attachments on the matching paper/step, delete the rows.
Tests for every point (numbers stable after void/back-date/rebuild; PI unchanged after route change;
buyer unchanged after customer edit until refresh; terms sentence per route).
